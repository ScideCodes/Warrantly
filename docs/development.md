# Development

Warrantly is an Android-first Expo / React Native app. Routes live in `src/app`, shared UI in `src/components`, local data in `src/db`, and Android integrations in `modules` and `plugins`.

## Requirements

- Node.js 22.18+ and npm.
- Android SDK and a device/emulator for local native builds, or an Expo account for cloud APK builds.
- Your own Google OAuth configuration for Google Drive sign-in. Register the Android package and signing SHA-1; a web OAuth client ID alone is insufficient. Never commit credentials or signing keys.

## Install dependencies and check

```sh
npm ci
npm run lint
npm run typecheck
npm test
```

Use `npx expo install <package>` when adding dependencies so versions match Expo SDK 58. Native directories are generated by Expo; configure native behavior through `app.json` and config plugins.

## Local development

```sh
npx expo run:android
```

This generates and builds the native Android app and starts Metro. On later runs, `npm start` starts Metro for the installed debug build. Expo Go cannot provide the scanner, Google sign-in, PDF renderer or widget modules.

## Cloud builds and OTA

```sh
npx eas-cli@latest build --platform android --profile preview
```

The preview profile produces a signed installable APK on the `preview` update channel. Cloud builds require your own EAS project and signing credentials. Installed release APKs run embedded/downloaded bundles, not Metro.

For compatible JavaScript and asset changes, commit and push, then:

```sh
npx eas-cli@latest update --channel preview --environment preview --platform android --message "Describe the change"
```

Native changes need a new compatible runtime and APK. See [releasing](releasing.md).

Gmail import is hidden in public 1.0 builds pending Google review. `EXPO_PUBLIC_GMAIL_IMPORT=1` is for the separate verification/staging flow only. Keep it unset for public updates. Drive backup remains available.

## Test notes

Node tests cover parsing, dates, database operations, backup encryption and import/export logic. UI/device checks must also cover English/Hungarian, light/dark themes, large fonts, three-button navigation and native integrations. The [1.0.0 release verification](release-1.0.0-verification.md) records the signed APK and Drive sign-in checks.
